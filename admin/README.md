# ちょんまげ 管理画面（/admin/）

公開サイトの TODAY（営業・イベント）と NEWS を編集する画面です。静的 GitHub Pages 上のツールなので、ログインや GitHub への自動アップロードはありません。編集した内容は「公開用ファイル」として保存し、GitHub にアップロードして公開します。

## 画面構成

| メニュー | 内容 |
| --- | --- |
| ホーム | 今日の日付、要確認のお知らせ、営業・イベント・リング・公開状態のまとめ、その日のスケジュール |
| 今日の予定 | 営業時間とリングゲーム、イベントの一覧（時間順）。「編集」で右側に編集パネルが開きます |
| News | NEWS 履歴を公開日時順に表示。Draft / Scheduled / Published / Expired と未反映の編集を表示 |
| 予約公開 | NEWS・イベント・ホームカードの予約を「今日 / 今週 / それ以降」でまとめて表示。予約日時の変更・今すぐ公開・予約の取消ができます。最近公開したものは折りたたみで確認できます |
| 設定 | 公式X のリンク、TODAY の説明文、データの扱い（自動取得に戻す・公開中に戻す・ファイルの中身） |

右上には常に「サイトを見る」「プレビュー」「下書き保存」「公開用ファイルを作成」があります。スマホではメニューが画面下に移ります。

## ホームの「要確認」

- 公開中の予定が今日の日付ではない（サイトに「公式Xをご確認ください」と表示されている）
- 入力に直すべき項目がある
- まだ公開していない変更がある
- 未来の日付の予定を編集中（公開しておくと、その日にサイトへ表示されます）

## ホームカード「今日のゲーム」

ホームの編集欄で日付を選び、営業状況・OPEN・MAIN TIME・MAIN EVENT・LATEST TEXT・X URL を入力します。曜日は日付から自動表示されます。MAIN の時刻と名称は両方空欄にすると非表示、X URL の空欄は既存の公式Xリンクを使います。

「プレビュー」で実際のホームカードを表示します。選択日モードでは未来日も確認でき、実際の日付モードでは日本時間の今日の設定だけを適用します。不正な入力中は最後の有効なプレビューを保持します。

「保存」はこのブラウザの既存の下書き保存です。公開サイトに反映するには既存の「公開用ファイルを作成」から3ファイルを GitHub の `data/` にアップロードしてください。「自動取得データに戻す」は確認後、選択日のホームカード設定だけを削除して下書き保存します。他の日付やイベント編集は残ります。こちらも公開にはアップロードが必要です。

手動カードは `events.manual.json` の `heroOverrides[YYYY-MM-DD]` に保持し、merge 後の `events.json` に含めます。当日の設定がなければ従来の自動・手動イベント表示と公式X案内をそのまま使います。自動取得は停止しません。

## イベントの編集

一覧ではイベント名・時間・参加費・最終受付だけを表示します。編集パネルでは、よく使う項目（イベント名・開始時間・種類・参加費・最終受付・短い説明）が先に並び、それ以外（終了時間・カードの色・トップ用の短い名前・MAIN 表示・その他の料金や詳細・タグ・リンク）は「詳細設定」の中にあります。

「…」メニューから 複製 / サイトで非表示 / 削除 ができます。非表示はデータを残したまま、サイトに出さない設定です。

新しいイベントの説明は空欄から始まります。仮文言「詳細を入力してください。」のままでは公開できません。

## 自動取得と手動編集

表示の優先順位は **手動編集 ＞ 自動取得 ＞ 公式X案内** です。

- 公式X から自動で読み取った値を変更すると、その項目にだけ「手動編集」と表示され、「自動の値に戻す」で元に戻せます。
- 手動で追加したイベントには「手動で追加」と表示されます。
- 自動取得の状態はサイドバー下（スマホでは 設定 → データの扱い）に表示されます。

## 公開の流れ

1. 「公開用ファイルを作成」を押す（入力に問題があれば、その項目が開きます）
2. 「3ファイルを保存」で `events.json` / `events.manual.json` / `news.json` を保存
3. GitHub のアップロード画面で `data/` の同名ファイルを置き換えて commit

この時点で初めてサイトに反映されます。`events.json` は GitHub Actions（`scripts/merge-events.mjs`）と同じ `scripts/schedule-core.mjs` の `mergeSchedule()` で作るので、Actions が作る結果と一致します。日付が自動取得の予定より前の場合は、公開されないため作成を止めます。ファイルの中身は「ファイルの中身を見る（上級者向け）」で確認できます。

## 下書き・プレビュー

- 「下書き保存」はこのブラウザ（localStorage）に保存します。次回開いたときに下書きから続けるか選べます。
- 「プレビュー」は実際の公開サイトを `?preview=1` で読み込み、下書きを表示します（スマホ / タブレット / PC 幅、「編集中の日付で表示」「今日の日付で判定」）。公開サイトそのものは変わりません。

## 検証

公開ページ（`script.js`）と Node / Actions（`scripts/schedule-core.mjs`）の両方の検証を通った内容だけ、プレビュー・公開用ファイルの作成ができます。

管理画面には `noindex,nofollow` を設定していますが、これは認証ではありません。秘密情報は入力しないでください。

## NEWS の管理

「＋ News を追加」は手動・下書きから始まります。タイトル、本文、短い説明、画像URL、公開日時（JST）、公開ON/OFF、情報源、X元投稿URLを編集できます。手動NEWSにはXリンクは不要です。「本文プレビュー」は実際のNEWS詳細のレンダラーで下書き・掲載終了も確認できます。詳細設定の固定表示も30日以内です。

- Draft：公開OFF。Scheduled：公開ONで未来の公開日時。Published：公開日時から30日以内。Expired：30日を超えた掲載終了。いずれも后台に残ります。
- Expired の公開日時を変更するか「今すぐ再公開」で同じIDを再公開できます。「コピーして下書きを作成」もできます。
- Xからの自動NEWSを編集・下架すると自動上書きを停止します。XからのNEWSを削除すると、そのURLを取得除外リストに保存して再追加を防ぎます。
- 状態は編集内容を公開した場合の状態です。「未反映の編集」がある間は現行サイトとの差分です。保存・公開用ファイル・GitHubアップロードは従来の同じ流れです。

## 予約公開

NEWS・イベント・ホームカードは、どれも編集画面の一番下にある同じ「公開方法」で公開時刻を選びます。

| 選択 | NEWS | イベント | ホームカード |
| --- | --- | --- | --- |
| 下書き | `published: false` | `hidden: true` | （なし） |
| 今すぐ公開 / 今すぐ適用 | 公開日時が現在以前 | `publishAt` なし | `publishAt` なし |
| 予約公開 / 予約適用 | 公開日時が未来 | `publishAt` に日時 | `publishAt` に日時 |

- 日時はすべて日本時間（JST）で、`2026-10-10T18:00:00+09:00` の形で保存します。NEWS は既存の `publishedAt`（表示日付も兼ねる）をそのまま予約日時として使います。
- 判定は共通の `publish-core.js` だけが行います。公開ページは開いたままでも1分以内に切り替わります。サーバーや Actions が時刻に何かを実行するわけではありません。
- 予約した内容も、これまで通り「公開用ファイルを作成」→ GitHub にアップロードして初めて有効になります。アップロード後は、時刻前でも `data/*.json` を直接開けば内容は読めます。発表前に絶対に見られてはいけない内容には使わないでください。
- イベントは編集中の日付の予定に属します。翌日以降のイベントは、これまで通りその日付の予定として作ってから予約してください。
- 複数の変更を同時刻にまとめて公開する機能（キャンペーン）はまだありません。誤って準備中の内容まで公開しないよう、1件ずつ予約します。
